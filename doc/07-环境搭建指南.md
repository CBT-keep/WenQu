## 1. 安装基础工具

### 1.1 Windows（推荐用 scoop 统一管理）

如果你还没装 scoop，先装（PowerShell，普通用户权限即可）：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
irm get.scoop.sh | iex
```

然后装工具：

```powershell
scoop install temurin17-jdk maven pnpm
```

> `pnpm` 的 scoop 包是 **standalone 版，自带 Node 运行时**，所以**不用单独装 Node.js** ——
> `pnpm dev` / `pnpm build` 都能直接跑。只有需要裸 `node xxx.js` 时才补 `scoop install nodejs-lts`。

**Docker Desktop 需要特殊处理**（要管理员 + 重启）：先下载安装包，再用脚本装。

```bash
# 下载（约 650MB，用 aria2 多线程比浏览器快很多）
aria2c -c -x 16 -s 16 -d ~/Downloads -o DockerDesktopInstaller.exe \
  "https://desktop.docker.com/win/main/amd64/Docker%20Desktop%20Installer.exe"
```

```powershell
# 右键 PowerShell → 以管理员身份运行
cd E:\Develop
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup-windows.ps1
```

脚本会自动启用 **WSL2** 和虚拟机平台、静默安装 Docker Desktop。
**结束后重启电脑**。

> 为什么必须 WSL2：Docker Desktop 在 Windows 上需要 Linux 内核环境，
> 这就是那条"必须从普通终端跳出来"的坎 —— 启用 Windows 功能需要提权，且必须重启才生效。

### 1.2 macOS

```bash
brew install temurin17 maven pnpm
brew install --cask docker
```

装完从 Launchpad 启动 Docker，接受条款，等托盘图标显示 running。
macOS 无 WSL 环节。

### 1.3 Linux（Debian / Ubuntu）

```bash
sudo apt update && sudo apt install -y openjdk-17-jdk maven
curl -fsSL https://get.pnpm.io/install.sh | sh -

# Docker Engine（官方脚本）
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # 注销重登后免 sudo
```

## 2. 配置国内镜像（**必做**）

这三处不改，后面基本走不动。全部已随仓库提供，照抄即可。

### ① Maven

```bash
cp scripts/maven-settings.xml ~/.m2/settings.xml
# Windows: copy scripts\maven-settings.xml %USERPROFILE%\.m2\settings.xml
```

IDEA 若没读到：Settings → Build Tools → Maven → **User settings file** 指向该文件。

> 两个坑：
> - 这个配置 `mirrorOf` 写的是 `central` 而**不是** `*`。
>   写 `*` 会把将来所有仓库（含私服）都代理走，内部依赖就拉不到了。
> - Maven 的 mirror **不会自动 failover**，同一 `mirrorOf` 只生效第一个。
>   阿里云异常时，把文件里华为云那段取消注释即可。

### ② npm / pnpm

**什么都不用做** —— 仓库根目录 `.npmrc` 已配好 `registry.npmmirror.com`，clone 后自动生效。

Node 本体建议从国内镜像下载：`https://registry.npmmirror.com/-/binary/node/`

### ③ Docker

Docker Desktop → Settings → **Docker Engine**，粘贴以下 JSON，点 Apply & Restart：

```json
{
  "builder": {
    "gc": {
      "defaultKeepStorage": "20GB",
      "enabled": true
    }
  },
  "experimental": false,
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me",
    "https://docker.m.daocloud.io"
  ]
}
```

> 顶部黄色警告是提醒"JSON 写错 Docker 会起不来" —— 所以**整段替换**，别手工拼。

验证：`docker info | grep -A 5 "Registry Mirrors"`，能看到三个地址即生效。

## 3. 起基础设施

```bash
cd <仓库根目录>
mkdir -p .wenqu-data/storage     # 文件存储目录（已在 .gitignore 中）
docker compose up -d
docker compose ps                # 等三个服务 STATUS 变为 healthy
```

首次会拉取三个镜像（pgvector 631MB + rabbitmq 277MB + rabbitmq 依赖层 + redis 58MB），
走加速源约 20～25 分钟。

`vector` 扩展由 `scripts/initdb/01-extensions.sql` 在容器**首次初始化时自动创建**，
不需要手工执行任何 SQL。

## 5. 常见问题（都实测踩过）

### 5.1 `java -version` 显示 21，但项目要 17

**不是问题**。pom 里 `java.version=17` 会被 Spring Boot parent 转成 `--release 17`，
即使用 JDK 21 编译，产物仍是 Java 17 字节码。误用 Java 21 新 API 会在编译期直接报错。

想彻底统一可切默认 JDK：`scoop reset temurin17-jdk`

验证产物版本：

```bash
javap -verbose -cp backend/target/classes xyz.cbt.wenqu.backend.BackendApplication | grep major
# major version: 61  →  Java 17
```

### 5.2 `docker: command not found`

新装 Docker 后，**已打开的终端 PATH 不会自动更新**。关掉重开一个新终端即可。

老终端里临时救急：

```bash
export PATH="/c/Program Files/Docker/Docker/resources/bin:$PATH"
```

### 5.3 `docker-credential-desktop: executable file not found`

同上，凭证助手程序的目录不在 PATH 里。重开终端即可（路径同 5.2）。

### 5.4 拉取中断：`could not fetch content descriptor ... (application/vnd.in-toto+json) from remote: not found`

**这不是网络故障。** `in-toto` 是 SLSA 供应链证明的格式，
部分加速源只同步镜像层、不同步 attestation，最后一步取证明时 404。

**镜像层其实已经下完了** —— 直接重跑：

```bash
docker compose up -d
```

已落地的层会被复用，第二次会跳过拉取、直接创建容器。
若反复失败，临时删掉 `registry-mirrors` 直连 Docker Hub，或换一个加速源。

### 5.5 加速源拉不动

公共加速源**时效性很强**（2024 年 6 月后曾大批失效）。自检某个源是否存活：

```bash
curl -I https://docker.1ms.run/v2/     # 返回 200 或 401 即为正常
```

长期最稳的是阿里云容器镜像服务控制台分配的**个人专属**地址
（形如 `https://xxxx.mirror.aliyuncs.com`），免费且稳定 —— 建议团队统一用同一个。

### 5.6 `pnpm-lock.yaml` 反复冲突

**不同大版本的 pnpm，lockfile 格式不兼容。** 团队必须统一 pnpm 大版本。

```bash
pnpm -v      # 应为 12.x
```

若机器上装了多个 pnpm（比如某些工具自带的隔离运行时），用 `pnpm -v` 确认实际生效的是哪个。

### 5.7 端口被占用（5432 / 6379 / 5672）

本机已装过 PostgreSQL / Redis 时会冲突。改 `docker-compose.yml` 的宿主机端口映射：

```yaml
ports:
  - "5433:5432"    # 左边是宿主机端口
```

同步改 `application.yaml` 的 `spring.datasource.url`。

### 5.8 想推倒重来

```bash
docker compose down -v     # 停止并删除数据卷（数据不可恢复，慎用）
docker compose up -d       # 重新初始化，initdb 会再次执行
```

## 6. 日常命令

```bash
docker compose up -d       # 启动
docker compose stop        # 停止（保留数据卷）
docker compose down        # 停止并移除容器
docker compose ps          # 查看状态
docker compose logs -f postgres   # 跟随日志

# 连数据库
docker compose exec postgres psql -U wenqu -d wenqu

# 看本地存储的文件
find .wenqu-data/storage -type f | head -20
du -sh .wenqu-data/storage
```

后端启动后 Flyway 会自动建表，无需手工执行 SQL：

```bash
cd backend && mvn spring-boot:run
```
