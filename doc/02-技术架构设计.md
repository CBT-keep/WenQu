**架构要点**

1. **单体分层**：本期不做微服务。按 `modules` 包内高内聚拆分，未来可按模块抽离。
2. **模型网关**：所有大模型调用统一经过 `LlmGateway`（基于 LangChain4j），屏蔽多供应商差异；
   支持超时、重试、降级（Chat 失败可回落备用模型）。
3. **两条引擎**：`RagEngine` 与 `SqlEngine` 互不依赖业务细节，仅通过 `LlmGateway` 与 `Mapper` 交互。
   二者的组合点是 `SqlEngine` 可选调用 `RagEngine.retrieve()` 获取指标口径。
4. **SSE 直连**：对话类接口使用 `POST + text/event-stream`，由 WebMvc 的 `SseEmitter`/`StreamingResponseBody` 提供；
   不走 WebSocket，降低复杂度。
5. **异步任务**：文档摄入与 Schema 同步为长任务，投递到 **RabbitMQ**（队列 `wenqu.ingest`、`wenqu.schema-sync`），
   消费者处理并推进 `kb_document.status` 等 DB 状态机，前端轮询状态接口。生产者在数据库提交后投递；定时补偿未领取任务，Redis 仅作加速，详见 §4.4。
6. **热状态**：Refresh Token 吊销、登录失败计数、系统参数缓存走 **Redis**；多实例部署下状态一致。
7. **文件存储**：原设计使用 MinIO（S3 兼容对象存储），**已改为本地文件系统**。
   通过 `StorageService` 接口抽象，本期实现 `LocalFileStorageService`；
   业务代码只依赖接口，将来要接 S3 / OSS 只需新增实现类并切换 `wenqu.storage.type`，无需改动上层。
   详见 §5.8。

### 3.2 模块依赖关系

- `common`、`config`、`security` 被所有模块依赖，自身不依赖业务模块。
- `chat` 依赖 `knowledgebase`（检索）与 `model`（网关）。

- `knowledgebase` 依赖 `model`、`common`。
- 严禁反向依赖（如 `knowledgebase` 依赖 `chat`）。

### 4.4 异步任务一致性与并发

本期采用“数据库任务版本 + 租约 + 周期补偿”方案，不新增独立 Outbox 表。文档记录和数据源同步记录均需保存 `task_version`、`task_lease_until`、`task_attempts`、`task_next_retry_at`；这是新增设计，需后续迁移，不修改已应用的 V1/V2。

- 事务提交任务状态/版本后发送 MQ，发布确认仅代表消息进入队列，不能替代数据库状态。每 30 秒扫描未领取、到重试时间或租约过期的任务重新投递，启动扫描作为补充。
- 消息携带资源 ID 和版本；消费者在事务中按版本及租约原子领取，处理时续租。过期版本与重复消息直接 ack；重建递增版本，旧消费者的写入必须带版本条件。
- 任务成功提交终态后 ack；失败持久化错误、释放租约，按指数退避重试（最多 3 次），耗尽后 FAILED 并进入死信处理。用户显式重试创建新版本。
- 文件先落盘，数据库失败时尝试补偿删除；孤儿清理仅处理超过 24 小时且二次核验无数据库引用的文件，避免误删上传中的文件。
- 配置修改、任务领取和删除共用资源行锁。删除运行中文档返回 `10004`，删除后旧版本写入无效。文件清理失败写操作日志，不能依赖已经删除的文档 `error_msg`。
- 同一会话只允许一个运行中生成任务，重复发送/重新生成返回 `10004`。先分配并持久化 assistant 消息再发 meta，成功落库后才发 done；停止时落库部分内容。断连取消任务并落库中止状态，客户端不自动重发 POST。

## 5. 关键技术方案

### 5.1 统一响应与异常

- 普通 JSON Controller 返回 `ApiResponse<T>`；`PageResult<T>` 承载分页；SSE 和下载/导出按各自协议直接返回。
- 业务异常抛 `BizException(ErrorCode)`；`@RestControllerAdvice` 统一兜底并记录 `traceId`。
- 参数校验失败由 `MethodArgumentNotValidException` 处理为 `10001`。

### 5.2 认证鉴权

- Spring Security 过滤器链：`JwtAuthenticationFilter` 前置，`/api/v1/auth/login`、`/auth/refresh`、
  健康检查、OpenAPI 白名单放行，其余 `authenticated()`。
- 方法级鉴权：`@PreAuthorize("hasAnyRole('ADMIN','SUPERADMIN')")` 控制管理类接口。
- 归属校验：Service 层调用 `ResourceGuard.checkOwner(resource)`（`@RequireOwner` AOP 或显式调用）。

### 5.3 模型网关（多模型可配置）

- `llm_model` 表是唯一事实来源；启动时与运行中变更（增删改）都会刷新内存注册表 `ModelRegistry`。
- `LlmGateway` 暴露统一方法：

```java
public interface LlmGateway {
    String chat(String modelKey, List<ChatMsg> messages, ChatOptions opts);
    void streamChat(String modelKey, List<ChatMsg> messages, ChatOptions opts, Consumer<String> onDelta);
    List<float[]> embed(String modelKey, List<String> texts);
    List<Float> rerank(String modelKey, String query, List<String> docs);
}
```

- 底层使用 LangChain4j 的 `OpenAiChatModel` / `OpenAiEmbeddingModel` / `OpenAiStreamingChatModel`
  针对每个配置项构建并缓存实例（`baseUrl` + `apiKey` + `modelName`）。
- RERANK：`bge-reranker-v2-m3` **无 OpenAI 标准接口**，由 `RerankClient` 按供应商协议适配
  （约定请求 `{model, query, documents[], top_n}` → 返回 `{results:[{index, relevance_score}]}`）。
  检索管线固定为：**bge-m3 向量召回 → bge-reranker-v2-m3 精排**（`rerankEnabled=true` 时启用）。

### 5.4 混合检索

```
score_final = RRF( rank_vector, rank_bm25 )            # 默认
            ↑ 权重可调：vector_weight / bm25_weight（系统参数）
若开启重排： 以 RRF 结果的前 N（默认 20）作为候选，交给 RERANK 模型重排后取 TopK
```

- 两路召回各自 TopK（默认 20），再融合。
- SQL 层面：向量用 `embedding <=> :qvec`（余弦距离，`vector_cosine_ops`），
  全文支路用 `tsv @@ plainto_tsquery('simple', :tokenizedQuery)` + `ts_rank_cd`。
- **查询串必须先分词**：`:tokenizedQuery` 不是用户的原始问句，而是经 `ChineseTokenizer`
  切分后以空格拼接的字符串（如 `'北京 天安门'`）。写入与查询必须用**同一个**分词器，
  否则召回失效。详见 §5.7。
- `scoreThreshold`（默认 0.35）只过滤向量支路的 `1 - cosine_distance`；全文支路不套用此阈值。RRF 原始分仅排序，不用 0.35 过滤；重排分单独展示，也不套用该阈值。响应 `score` 为启用重排时的重排分，否则为原始 RRF 分（VECTOR 模式为余弦相似度，BM25 模式为全文排名分）；必须结合 mode/rerankUsed 解读。
- 先按权限、kb_id、READY 和非失效索引过滤，各路各取候选；融合后先取 rerankCandidates 再重排，最后取 topK；不开重排则直接取 topK。
- 本期保留 API 枚举 `BM25` 和 `bm25*` 字段名以兼容既有契约，但实际算法为 PostgreSQL `ts_rank_cd` 覆盖密度排序，Lucene 仅分词，并未实现 BM25。`plainto_tsquery` 默认 AND；本期按全部有效词命中执行，空词元返回空结果，后续调整 OR 召回应显式修改契约。

### 5.5 动态数据源（SQLBot）

- 不为每个数据源建 Spring 数据源 Bean（数量不可控），改用**每次连接新建 HikariDataSource 并缓存**的
  `DynamicDataSourceManager`（LRU + 空闲回收），或直接 `DriverManager` + 短连接。
  推荐前者（连接复用），配置 `maximumPoolSize` 取自数据源记录。
- 执行前设置：`connection.setReadOnly(true)`、`statement.setQueryTimeout(timeoutSec)`、`setMaxRows(maxRows+1)`。

### 5.6 SQL 安全校验

1. 用支持 PostgreSQL 的 SQL 解析器生成 AST，仅接受单条 SELECT（含只读 WITH）；递归拒绝写 CTE、SELECT INTO、行锁及非白名单函数，解析失败时拒绝，不退回关键词校验。关键词黑名单仅辅助。
2. EXPLAIN 独立处理：只允许目标为上述安全 SELECT 的普通 EXPLAIN，拒绝 ANALYZE；不得将 EXPLAIN 包装为子查询。
3. 每次执行检查数据源权限；使用最小权限只读账号、显式只读事务及数据库 `statement_timeout`，同时设置 JDBC 超时；不依赖账号建议或 `setReadOnly` 单独兜底。
4. SELECT 通过 AST 重写外层 LIMIT，保留原来更小的 LIMIT，最多取 `maxRows+1`；JDBC `setMaxRows(maxRows+1)` 二次限制。手工执行、导出、样例读取均应用对应权限与安全规则。
5. 普通查询 maxRows 不超过系统上限；导出使用独立 export-max-rows 上限。超出普通查询上限截断并置 truncated=true；导出检测超限返回 60007。

### 5.7 文档解析与切分

- Tika `AutoDetectParser` + `BodyContentHandler` 抽纯文本；HTML 走 `HtmlMapper` 保留结构。
- 清洗：去页眉页脚噪声、合并多余空白、规范化换行。
- 切分：`RecursiveCharacterTextSplitter` 语义分隔符优先级 `["\n\n","\n","。","！","？","；"," ",""]`，
  以 **token** 计量（非字符），支持块大小与重叠。
- **分词（BM25 用）**：每个分片在入库前经 `ChineseTokenizer` 切词，
  词元以空格拼接后写入 `kb_chunk.tsv`（`to_tsvector('simple', ...)`）。见 §5.7.1。

#### 5.7.1 中文分词（应用层 Lucene）

原设计采用 PG 扩展 `zhparser`，已废弃 —— 它需要编译安装，是环境搭建最大的障碍，
且在 Windows 上无法使用。改为**应用层分词**，数据库侧只用 PostgreSQL 内置的 `simple` 文本搜索配置：

```java
@Component
public class ChineseTokenizer {
    private final Analyzer analyzer = new SmartChineseAnalyzer();   // 可换 IKAnalyzer

    /** 写入侧：content → '我 爱 北京 天安门' */
    public String tokenize(String content) {
        List<String> tokens = new ArrayList<>();
        try (TokenStream ts = analyzer.tokenStream("content", content)) {
            CharTermAttribute attr = ts.addAttribute(CharTermAttribute.class);
            ts.reset();
            while (ts.incrementToken()) tokens.add(attr.toString());
            ts.end();
        } catch (IOException e) { throw new BizException(ErrorCode.TOKENIZE_FAILED); }
        return String.join(" ", tokens);
    }
}
```

- 写入：`INSERT INTO kb_chunk (..., tsv) VALUES (..., to_tsvector('simple', :tokenized))`
- 查询：`plainto_tsquery('simple', :tokenizedQuery)`
- **写入与查询必须使用同一个 `ChineseTokenizer` 实例**（同一词典、同一停用词表），否则召回失效。
- 带来的额外好处：
  - 跨平台结果完全一致（Windows / macOS / Linux 无差异）
  - 业务词典可控：可加载自定义词表（如「月活」「口径」「GMV」），
    改词典后须重建已有分片 tsv；查询与索引的分词器版本一致后切换，无需重新编译数据库扩展
  - `tsv` 从 GENERATED 列改为应用层写入的普通列（DDL 见 [`03`](./03-数据库设计.md) §4.5）

### 5.8 本地文件存储约定

原设计的 MinIO（S3 兼容对象存储）已废弃，改为**本地文件系统**。

**接口抽象（核心）**

```java
public interface StorageService {
    /** 写入文件，返回实际落盘的相对路径 */
    String put(String relativePath, InputStream in, String contentType);
    /** 读取为 Spring Resource，供 Controller 流式响应 */
    Resource load(String relativePath);
    void delete(String relativePath);
    boolean exists(String relativePath);
}
```

本期实现 `LocalFileStorageService`；`wenqu.storage.type` 预留 `s3` 值，
将来需要对象存储时新增实现类即可，业务代码与 Controller 无需改动。

| 项 | 约定 |
|---|---|
| 存储根目录 | `wenqu.storage.local.root`，默认 `${WENQU_DATA_DIR:./.wenqu-data}/storage` |
| 文件相对路径 | `kb/{kbId}/doc/{yyyy}/{MM}/{uuid}.{ext}`，存入 `kb_document.file_key` |
| 下载方式 | **后端鉴权接口** `GET /api/v1/documents/{docId}/download`，走 `Resource` 流式返回（见 [`04`](./04-API接口规范.md) §6.6） |
| 删除 | 先在事务中读取待删 file_key 并删除 DB 记录，提交后异步删文件；失败写操作日志，由孤儿文件清理任务兜底 |
| 上传限制 | 单文件 50MB、单次 20 个（应用层 + 前端双重限制） |

**必须落实的四条安全约束**

1. **路径穿越防护**：`relativePath` 必须经 `normalize()` 后校验 `startsWith(root)`，
   否则形如 `../../etc/passwd` 的键名会读到任意文件。
2. **文件名不采信**：落盘文件名由服务端生成 UUID，用户原始文件名只写 `kb_document.name` 用于展示
   —— 同时规避中文/特殊字符在 Windows 上的编码问题。
3. **下载走鉴权**：不再有"任何人拿到 URL 就能下载"的预签名链接，
   `ResourceGuard.checkOwner()` 对每次下载生效，USER 只能下载自己的文档。
4. **孤儿文件清理**：定时任务比对磁盘文件集合与 DB `file_key` 集合，清理无主文件。

> **备份**：整个 `.wenqu-data` 目录打包即可，比对象存储更简单。
> 需在 `.gitignore` 中排除 `.wenqu-data/`。

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| LangChain4j 与 Spring Boot 4 的兼容性 | 模型接入（**风险已降级**） | 官方已明确支持 Boot 4（`-spring-boot4-starter` 后缀，要求 Java 17）。我们仍**不使用其 Starter** —— `LlmGateway` 需按 `llm_model` 表在运行时动态构建/销毁模型实例，静态自动装配不匹配；只用核心 + provider 模块。T0 仍需实测一次 |
| 中文分词质量 | 影响混合检索召回率 | 应用层 Lucene `smartcn`；内置词典对垂直领域词（如「月活」「口径」）覆盖不足时加载自定义词表。BM25 只是混合检索的一路，最差情况可在系统参数关闭 BM25、降级为纯向量 |
| pgvector 维度固定 | 换 embedding 模型需重建索引 | 全局锁定维度；切换模型视为一次"全量重建"运维动作（计划任务 + 双写过渡） |
| 本地存储磁盘写满 | 上传失败、应用异常 | 启动时校验剩余空间，低于阈值告警；系统参数限制单库容量；存储目录建议挂独立数据盘 |
| 本地存储无法多实例共享 | 水平扩展时文件不可见 | 本期单体单实例部署不受影响；需要水平扩展时切换 `wenqu.storage.type=s3` 并新增实现类，业务代码不动 |
| SSE 在网关/代理下被缓冲 | 流式失效 | Nginx 关闭 `proxy_buffering`；响应头 `X-Accel-Buffering: no`；心跳保活 |
| 大模型超时/限流 | 对话与查数失败 | 网关层超时 + 重试 + 备用模型；错误以 SSE `error` 事件返回而非连接断开 |
| 动态数据源连接泄漏 | 拖垮应用 | 连接池缓存 + 空闲回收 + 强制超时；监控活跃连接数 |
| 长文本超上下文窗口 | 生成质量差 | Prompt 层按 token 预算裁剪引用片段；超出阈值减少 TopK |
| 消费者崩溃导致消息丢失 | 摄入卡死 | RabbitMQ 消息持久化 + 手动 ack；启动及每 30 秒扫描未领取/租约过期任务重新入队（文档及 Schema 同步共用 §4.4 规则）；死信队列 `wenqu.ingest.dlx` |
| Redis 不可用 | 登录/限流失效 | Refresh 校验查权威 `sys_refresh_token`；数据库也不可用时拒绝刷新。登录限流降级为 DB 连续失败规则，不直接放行 |
