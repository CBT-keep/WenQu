## 1. P1 · 认证与权限

### AUTH-01 登录失败记录持久化与连续失败锁定

- [ ] 修复失败记录随登录事务回滚的问题。
- [ ] 实现连续失败计数、成功登录清零、达到阈值锁定及到期解锁。
- [ ] 按既定架构使用 Redis 维护热状态，数据库保留审计与降级依据，明确 Redis 故障时的处理方式。
- [ ] 补充并发失败登录测试，避免计数丢失或绕过阈值。

**现状**：`AuthServiceImpl.login()` 在 `@Transactional` 内写失败记录后抛出 `BizException`（运行时异常），记录会回滚。`LoginAttemptRepository.countRecentFailures()` 统计窗口内全部失败，成功登录不会重置，和“连续失败”规则不一致。

**验收**：错误密码记录在请求结束后仍存在；连续失败达到配置阈值后拒绝登录；成功登录清除之前的失败计数；锁定到期可以重新登录；并发请求下计数符合规则。

**涉及文件**：[AuthServiceImpl](../backend/src/main/java/xyz/cbt/wenqu/backend/modules/auth/service/impl/AuthServiceImpl.java)、[LoginAttemptRepository](../backend/src/main/java/xyz/cbt/wenqu/backend/modules/auth/mapper/LoginAttemptRepository.java)。

### AUTH-02 禁用账号立即禁止访问

- [ ] JWT 过滤器认证前检查用户是否启用，禁用用户不能写入安全上下文。
- [ ] 保持刷新令牌接口的禁用检查，统一错误响应。

**现状**：`JwtAuthenticationFilter` 查出用户后直接创建已认证对象，没有检查 `isEnabled()`。仅吊销 Refresh Token 不能阻止已有 Access Token 访问。

**验收**：用户登录后被禁用，携带原 Access Token 调用受保护接口被拒绝，原 Refresh Token 也不能刷新；正常启用用户访问不受影响。

**涉及文件**：[JwtAuthenticationFilter](../backend/src/main/java/xyz/cbt/wenqu/backend/modules/auth/filter/JwtAuthenticationFilter.java)、[UserServiceImpl](../backend/src/main/java/xyz/cbt/wenqu/backend/modules/user/service/impl/UserServiceImpl.java)。

### AUTH-03 在后端落实强制改密

- [ ] 为 `must_change_password=true` 的用户增加后端访问限制。
- [ ] 明确允许访问的必要接口（查看本人、修改本人密码、登出及必要的认证流程），其余业务接口拒绝访问。
- [ ] 修改密码成功后解除限制，返回符合 API 规范的错误响应。

**现状**：当前只将 `mustChangePassword` 返回前端，安全过滤器和权限配置没有执行限制，可以绕过前端调用业务接口。

**验收**：初始管理员和被重置密码的用户无法直接调用用户管理等业务接口；允许修改本人密码；改密成功后按角色正常访问。

**涉及文件**：[SecurityConfig](../backend/src/main/java/xyz/cbt/wenqu/backend/config/SecurityConfig.java)、[JwtAuthenticationFilter](../backend/src/main/java/xyz/cbt/wenqu/backend/modules/auth/filter/JwtAuthenticationFilter.java)。

## 2. P2 · 令牌、审计与规则一致性

### AUTH-04 修改或重置密码后使已有访问令牌失效

- [ ] 为密码变更引入可校验的令牌失效机制，例如用户凭证版本；涉及表结构时新增迁移，保留历史迁移文件。
- [ ] 本人改密、管理员重置密码时，使该用户此前签发的 Access Token 和 Refresh Token 全部失效。
- [ ] 与 AUTH-02 共用清晰的账号状态及令牌校验流程。

**现状**：两个改密入口都仅吊销 Refresh Token，已有 Access Token 仍有效，达不到代码注释中的“秒踢”。

**验收**：改密或重置后，所有旧访问令牌和刷新令牌被拒绝；新密码登录成功，旧密码登录失败。

**涉及文件**：[AuthServiceImpl](../backend/src/main/java/xyz/cbt/wenqu/backend/modules/auth/service/impl/AuthServiceImpl.java)、[UserServiceImpl](../backend/src/main/java/xyz/cbt/wenqu/backend/modules/user/service/impl/UserServiceImpl.java)、[JwtUtil](../backend/src/main/java/xyz/cbt/wenqu/backend/utils/JwtUtil.java)。

### USER-01 统一审计入口并隔离事务

- [ ] 合并 Controller 的 `@OpLog` 与 Service 手动 `audit()`，避免同一次操作重复记录。
- [ ] 让审计持久化与业务事务隔离，日志写入失败不能使业务事务回滚；成功日志应在业务成功提交后产生。
- [ ] 统一日志类型、动作和结果值，符合 API 文档口径；保留失败记录、操作者、目标、IP 和 traceId。

**现状**：用户管理的写操作会通过两套入口写日志。Service 手动写日志处于业务事务中，即使捕获异常，数据库错误仍可能导致事务无法提交。

**验收**：每次操作仅产生一条对应审计记录；业务回滚不记录成功；模拟日志写入失败时业务仍按既定规则提交；密码和令牌不进入日志明文。

**涉及文件**：[UserServiceImpl](../backend/src/main/java/xyz/cbt/wenqu/backend/modules/user/service/impl/UserServiceImpl.java)、[OpLogAspect](../backend/src/main/java/xyz/cbt/wenqu/backend/common/log/OpLogAspect.java)、[OpLogWriter](../backend/src/main/java/xyz/cbt/wenqu/backend/common/log/OpLogWriter.java)。

### AUTH-05 统一密码校验规则

- [ ] 抽取统一密码规则，覆盖创建用户、管理员重置密码、用户自行改密。
- [ ] 统一执行 8–64 位且包含字母和数字的规则，避免仅依赖不同 DTO 的局部校验。

**现状**：`UserServiceImpl.validatePassword()` 检查长度和字母数字；`ChangePasswordDTO` 只检查长度，自行改密可以使用纯数字密码。

**验收**：三个入口均拒绝长度不符、纯数字、纯字母密码；合法密码和服务端生成的临时密码均通过。

**涉及文件**：[ChangePasswordDTO](../backend/src/main/java/xyz/cbt/wenqu/backend/modules/auth/dto/ChangePasswordDTO.java)、[AuthServiceImpl](../backend/src/main/java/xyz/cbt/wenqu/backend/modules/auth/service/impl/AuthServiceImpl.java)、[UserServiceImpl](../backend/src/main/java/xyz/cbt/wenqu/backend/modules/user/service/impl/UserServiceImpl.java)。
