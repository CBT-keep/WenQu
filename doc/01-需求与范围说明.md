## 1. 项目背景与目标

**一句话**：让企业内部用户可以「查文档」和「查数据」不再依赖人工，而是用自然语言直接完成。

两个核心能力：

1. **RAG（检索增强生成）**：用户上传 PDF/Word/Markdown 等文档，系统解析、切分、向量化后存入知识库；
   用户提问时先检索相关片段，再交给大模型生成带**引用溯源**的回答。
2. **SQLBot（NL2SQL）**：用户用自然语言描述想查的数据，系统结合数据库 Schema 生成 SQL 并执行，
   以**表格 + 图表**呈现结果，可导出。

**二者的结合点**：SQLBot 生成 SQL 时，可以额外检索一个专门的"指标口径知识库"，
把"销售额""活跃用户"等业务口径作为上下文喂给模型，提升 NL2SQL 的准确性与一致性。

### 目标（本期）

- 跑通 RAG 与 NL2SQL 两条主链路，做到可用。
- 后端提供稳定、规范、可文档化的 REST/SSE 接口。
- 具备基础的多用户、多角色、审计能力。

### 非目标（本期不做）

- 不做跨多种数据库类型的 SQL 方言适配（本期仅 PostgreSQL）。
- 不做仪表盘/大屏、定时报表、数据订阅推送。
- 不做 OCR / 扫描件版面还原。
- 不做多租户（组织隔离）——按"资源归属人 + 角色"隔离。
- 不做开放自助注册。

## 2. 角色与权限

三层角色，自上而下包含关系（高角色拥有低角色的全部资源权限）。

| 角色 | 标识 | 能力 |
|---|---|---|
| 超级管理员 | `SUPERADMIN` | 拥有 `ADMIN` 全部能力；**独占**用户管理、系统参数、操作日志、模型配置 |
| 管理员 | `ADMIN` | 管理**全平台**的知识库、文档、会话；数据源仅本人；可查看统计；不能管理用户与系统参数 |
| 普通用户 | `USER` | 仅能操作**自己创建**的资源（知识库 / 数据源 / 会话） |

### 权限矩阵

| 能力 | USER | ADMIN | SUPERADMIN |
|---|:--:|:--:|:--:|
| 登录 / 查看自己信息 / 改自己密码 | ✅ | ✅ | ✅ |
| 创建、管理自己的知识库与文档 | ✅ | ✅ | ✅ |
| 查看并管理**全部**知识库与文档 | ❌ | ✅ | ✅ |
| 使用智能问答、检索测试 | ✅ | ✅ | ✅ |
| 创建、管理自己的数据源 | ✅ | ✅ | ✅ |
| 管理**全部**数据源（含生产库连接信息） | ❌ | ❌ | ✅ |
| 使用 SQLBot 查询 / 导出 | ✅ | ✅ | ✅ |
| 创建、管理自己的会话（RAG / SQLBot） | ✅ | ✅ | ✅ |
| 查看平台统计仪表盘 | ❌ | ✅ | ✅ |
| 模型配置（增删改 / 连通性测试） | ❌ | ❌ | ✅ |
| 用户管理（创建 / 禁用 / 重置密码 / 删除） | ❌ | ❌ | ✅ |
| 系统参数、操作日志 | ❌ | ❌ | ✅ |

> **归属判定规则**：资源表统一带 `owner_id`。
> - 知识库 / 文档 / 会话：`SUPERADMIN`/`ADMIN` 放行，`USER` 仅当 `owner_id == 当前用户`；
> - **数据源（含连接信息，敏感）**：`SUPERADMIN` 放行，`ADMIN`/`USER` 仅当 `owner_id == 当前用户`。
>
> 不满足则返回 `20006 无权限`。
> 该规则集中在后端 `ResourceGuard` 组件，接口层面通过注解 `@RequireOwner` 声明。

## 3. 功能范围（模块 → 功能点）

### 3.1 认证与会话

- 用户名 + 密码登录，签发 Access Token（2h）与 Refresh Token（7d）。
- 刷新令牌、登出（令牌吊销）、查看当前用户信息、修改本人密码。
- 连续登录失败锁定（默认 5 次 / 锁 30 分钟）。
- 无自助注册入口。

### 3.2 系统管理（SUPERADMIN）

- **用户管理**：列表（分页/检索/筛选）、创建、编辑、启用禁用、重置密码、删除；不可删除自己。
- **模型配置**：管理多供应商模型，类型分 `CHAT / EMBEDDING / RERANK`；含 base_url、api_key、模型名、
  向量维度（EMBEDDING 必填）、温度、最大 Token 等；支持连通性测试、设为默认、启用禁用。
- **系统参数**：RAG 全局参数（混合检索权重、默认 TopK、阈值、默认切分大小/重叠）、
  SQLBot 安全参数（最大返回行数、超时、连接池、语句白名单/黑名单）、日志与会话保留天数。
- **操作日志**：按时间/类型/操作人/IP 检索，记录登录、写操作、SQL 执行、配置变更；支持导出。

### 3.3 RAG 知识库管理

- **知识库 CRUD**：名称、描述、绑定 embedding 模型、切分配置、检索配置；归属人为创建者，本期不可转移；可见性仅 PRIVATE 生效。
- **文档管理**：上传（多文件）、列表（状态/分页/检索）、下载、删除、重建索引、失败重试。
- **分片管理**：查看某文档的分片列表、分片详情、编辑分片内容（触发重新向量化）、删除分片。
- **检索测试**：独立于对话，输入查询语句，返回命中片段、各路得分（向量/BM25/重排）、耗时。
- **摄入流水线状态可视化**：文档级 `PENDING → PARSING → CHUNKING → EMBEDDING → READY | FAILED`。

### 3.4 智能问答（RAG 对话）

- 会话 CRUD、会话内消息分页拉取。
- 发送消息 → **SSE 流式**返回：先返回检索引用，再逐字返回生成内容，最后返回用量统计。
- 回答中的引用角标可点开查看来源片段（文档名 / 章节 / 分片 / 相似度）。
- 消息反馈（👍/👎）、重新生成、停止生成、复制。
- 会话级别可切换"引用哪些知识库"与"使用哪个 Chat 模型"。

### 3.5 SQLBot 自然语言查询

- **数据源管理**：连接信息 CRUD、连接测试、Schema 同步（异步 + 状态查询）。
- **Schema 浏览**：表列表、字段详情、主外键、注释、样例行；可启用/禁用某张表参与 NL2SQL。
- **NL2SQL 对话**：自然语言 → 展示生成的 SQL 与解释 → 流式返回执行结果 → 图表渲染。
- **手工执行**：可直接编辑 SQL 后执行（仍走安全校验），支持 EXPLAIN。
- **结果导出**：CSV / Excel。
- **安全约束**：只读（仅 SELECT/EXPLAIN/WITH）、语法树校验、数据库只读事务、返回行数限制、超时熔断；关键词黑名单仅辅助校验。

## 4. 核心用户故事

| 编号 | 角色 | 故事 | 验收要点 |
|---|---|---|---|
| US-01 | SUPERADMIN | 我创建用户并分配角色 | 创建后可用该账号登录；USER 看不到系统管理菜单 |
| US-02 | SUPERADMIN | 我配置一个 OpenAI 兼容的 Chat 模型并测试连通 | 测试成功返回模型回显；可设为默认 |
| US-03 | USER | 我创建知识库并上传 5 个 PDF | 上传后异步解析，列表能看到状态从解析中变为已就绪 |
| US-04 | USER | 我在检索测试里验证召回效果 | 能看到每个片段的得分与来源，可切换检索方式 |
| US-05 | USER | 我基于知识库提问，答案带引用 | SSE 流式逐字输出；引用角标可展开来源 |
| US-06 | USER | 我连接一个 PostgreSQL 数据源并同步 Schema | 同步后能浏览表与字段 |
| US-07 | USER | 我用自然语言查"各区域上月销售额前5" | 生成 SQL 可见、可编辑；结果表格+图表；可导出 CSV |
| US-08 | USER | 我尝试执行 `DROP TABLE` | 被安全校验拦截并提示 |
| US-09 | SUPERADMIN | 我调整混合检索权重 | 修改指定知识库权重后对其新检索生效；全局权重仅作为新库默认值，均写入操作日志 |
| US-10 | ADMIN | 我查看某用户误删的知识库 | 能列出全平台知识库（ADMIN 越权可见） |

## 5. 边界与约束

### 5.1 性能与容量（设计目标，非硬性 SLA）

| 指标 | 目标 |
|---|---|
| 单文档最大体积 | 50 MB |
| 单次上传文件数 | 20 |
| 单知识库分片规模 | ≤ 100 万（pgvector HNSW 可支撑） |
| 检索延迟（TopK=8，混合） | P95 < 800ms（不含重排）/ < 1.5s（含重排） |
| 首 Token 延迟（问答） | P95 < 3s |
| SQL 执行超时 | 默认 10s |
| 单次查询最大返回行数 | 默认 1000（可配置，导出上限 10 万） |

### 5.2 技术约束

- 向量维度**全局统一**（已确认，取 `bge-m3` 的 **1024**）：pgvector 列维度固定，创建知识库时校验所选 embedding 模型维度 == 全局维度，
  否则报 `40006 向量维度不匹配`。
- 中文 BM25 分词采用**应用层 Lucene `smartcn`** + PostgreSQL 内置 `simple` 文本搜索配置，
  **不安装 zhparser**（需编译安装，且在 Windows 上不可用）。数据库侧只需 `pgvector` 一个扩展。
- 重排管线已确认：**bge-m3 向量召回 → bge-reranker-v2-m3 精排**。
- 引入 **RabbitMQ**：文档摄入、Schema 同步走队列（`wenqu.ingest` / `wenqu.schema-sync`），消息持久化 + 手动 ack + 死信队列；DB 状态机仍是唯一事实来源。
- 引入 **Redis**：Refresh Token 活跃缓存（数据库为权威）、登录失败计数、系统参数缓存；`sys_refresh_token` / `sys_login_attempt` 表保留作审计与降级兜底。

### 5.3 安全约束

- 密码使用 BCrypt（cost 10）存储；API Key / 数据源密码在库中**加密存储**（AES-GCM），返回时脱敏。
- SQLBot 连接统一使用**只读账号**（文档强提示），并在应用层二次校验语句类型。
- 所有写操作与敏感读操作写入 `sys_operation_log`。
- 上传文件类型白名单校验（扩展名 + MIME + Tika 探测），本地文件存储中使用 UUID 文件名，防路径穿越。
