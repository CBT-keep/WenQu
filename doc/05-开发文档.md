## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 17 | 与 `pom.xml` 的 `java.version=17` 一致（Spring Boot 4 基线） |
| Maven | 3.9+ | 或直接用项目自带 `mvnw`（已改走阿里云镜像） |
| pnpm | 12+ | 前端包管理（`.npmrc` 已配好镜像，clone 即生效） |
| Docker | 24+ | 起 PostgreSQL / Redis / RabbitMQ（Windows 上依赖 WSL2，见 §2.4） |

**不再需要**：~~MinIO~~（文件存储改本地磁盘）、~~zhparser~~（分词改应用层 Lucene）。
全项目的外部依赖收敛为 **PostgreSQL（含 pgvector）+ Redis + RabbitMQ** 三个容器。

> ⚠️ **国内网络请先做 §2.3 的加速配置**，否则 Maven / npm / Docker 三处都会卡住。

**推荐用 scoop 统一管理（Windows）**

```bash
scoop install temurin17-jdk maven pnpm
```

pnpm 的 scoop 包是 **standalone 版**，自带 Node 运行时，因此**不必单独装 Node.js** ——
`pnpm dev` / `pnpm build` 都能正常跑。只有在需要裸 `node xxx.js` 时才补装 `scoop install nodejs-lts`。

> ⚠️ **注意 PATH 优先级**：若机器上已有其他 Node/pnpm（比如某些工具自带的隔离运行时），
> 用 `pnpm -v` 确认实际生效的版本。团队需统一 pnpm 大版本 —— 不同大版本的 lockfile
> 格式不兼容，混用会导致 `pnpm-lock.yaml` 反复冲突。

**建议 IDE 插件**：Lombok、MapStruct（若使用）、Spring Boot Assistant、Tailwind CSS IntelliSense。

## 2. 基础设施（docker-compose）

仓库根目录 `docker-compose.yml` 提供三个服务，开箱即用：

```yaml
services:
  postgres:
    image: pgvector/pgvector:pg16
    container_name: wenqu-postgres
    environment:
      POSTGRES_DB: wenqu
      POSTGRES_USER: wenqu
      POSTGRES_PASSWORD: wenqu@123
      TZ: Asia/Shanghai
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
      # 首次启动自动执行 CREATE EXTENSION vector
      - ./scripts/initdb:/docker-entrypoint-initdb.d:ro
    # 并行构建 HNSW 索引需要更大的共享内存
    shm_size: 1g
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U wenqu -d wenqu"]
      interval: 5s
      timeout: 3s
      retries: 10

  redis:
    image: redis:7-alpine
    container_name: wenqu-redis
    ports:
      - "6379:6379"
    command: redis-server --appendonly yes
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10

  rabbitmq:
    image: rabbitmq:3.13-management-alpine
    container_name: wenqu-rabbitmq
    ports:
      - "5672:5672"
      - "15672:15672"   # 管理台
    environment:
      RABBITMQ_DEFAULT_USER: wenqu
      RABBITMQ_DEFAULT_PASS: wenqu@123
    volumes:
      - rabbitmq_data:/var/lib/rabbitmq
    healthcheck:
      test: ["CMD", "rabbitmq-diagnostics", "-q", "ping"]
      interval: 10s
      timeout: 5s
      retries: 10

volumes:
  pgdata:
  redis_data:
  rabbitmq_data:
```

启动并确认就绪（等三个服务 `STATUS` 变为 `healthy`）：

```bash
docker compose up -d
docker compose ps
docker compose exec postgres psql -U wenqu -d wenqu \
  -c "SELECT extversion FROM pg_extension WHERE extname='vector';"
```

`vector` 扩展由 `scripts/initdb/01-extensions.sql` 在容器首次初始化时自动创建，
表结构则由后端 Flyway 迁移负责。

### 2.1 中文 BM25 分词（应用层 Lucene，不装任何 PG 扩展）

原设计采用 PG 扩展 `zhparser`，**已废弃**。原因：需要自定义镜像编译安装，
是环境搭建最大的障碍，且在 Windows 上无法使用。

现改为应用层分词，数据库侧只用 PostgreSQL **内置**的 `simple` 文本搜索配置：

| 环节 | 做法 |
|---|---|
| 写入 | `content` → Lucene `SmartChineseAnalyzer` 切词 → 空格拼接 → `to_tsvector('simple', :tokenized)` |
| 查询 | 用户问句 → **同一个**分词器切词 → `plainto_tsquery('simple', :tokenizedQuery)` |

因此 `docker-compose.yml` 直接使用 pgvector 官方镜像，**不需要任何自定义 Dockerfile**。
`tsv` 列也从 GENERATED 列改为应用层显式写入的普通列，DDL 见 [`03`](./03-数据库设计.md) §4.5。
依赖见 §3.1。

> 若 `smartcn` 的词典对垂直业务词（如「月活」「口径」「GMV」）覆盖不足，
> 可换 `IKAnalyzer` 或在 `SmartChineseAnalyzer` 之上叠加自定义词表 —— 改词典重启应用即可，
> 无需像 zhparser 那样重新编译数据库扩展。

### 2.3 国内网络加速（首次搭建必做）

三处配置已随仓库提供，照做即可，不要各自去搜。

**① Maven**

```bash
# 仓库内已提供，复制到用户目录即可
cp scripts/maven-settings.xml ~/.m2/settings.xml
# Windows PowerShell：
# copy scripts\maven-settings.xml %USERPROFILE%\.m2\settings.xml
```

> `mvnw` 的 `distributionUrl` 已改走阿里云 Apache 镜像，无需再手工下载 Maven 发行包。
> 若 IDEA 未读到：Settings → Build Tools → Maven → User settings file 指向该文件。
> 注意：Maven 的 `mirrorOf` **不会自动 failover**，阿里云异常时把文件里华为云那段取消注释即可。

**② npm / pnpm**

仓库根目录 `.npmrc` 已配置 `registry.npmmirror.com`，clone 后自动生效，无需手工执行任何命令。

Node.js 本体建议从国内镜像下载：`https://registry.npmmirror.com/-/binary/node/`
（或用 `nvm` 设置 `NVM_NODEJS_ORG_MIRROR` 环境变量）。

**③ Docker**

Docker Desktop → Settings → Docker Engine，加入 `registry-mirrors`：

```json
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me",
    "https://docker.m.daocloud.io"
  ]
}
```

Apply & Restart 后验证：`docker info | grep -A 5 "Registry Mirrors"`。

> ⚠️ **公共加速源时效性很强**（2024 年 6 月后曾大批失效），拉不动就换下一个。
> 快速自检某个源是否存活（返回 200 或 401 即为正常）：
> ```bash
> curl -I https://docker.1ms.run/v2/
> ```
> 最稳的长期方案是阿里云容器镜像服务控制台分配的**个人专属**地址
> （形如 `https://xxxx.mirror.aliyuncs.com`），免费且稳定。

> ⚠️ **已知坑（实测遇到）：加速源缺供应链证明导致拉取中断**
>
> 部分加速源只同步镜像层，不同步 SLSA 供应链证明（attestation）。拉取时会报：
> ```
> failed to copy: httpReadSeeker: failed open: could not fetch content descriptor
> sha256:xxxx (application/vnd.in-toto+json) from remote: not found
> ```
> **这不是网络故障** —— 镜像层其实已经下载完了，只是最后一步取 attestation 时 404。
> **直接重跑 `docker compose up -d` 即可**，已落地的层会被复用，第二次会跳过拉取、
> 直接进入创建容器阶段。若反复失败，临时删掉 `registry-mirrors` 直连 Docker Hub，或换个加速源。

### 2.4 Windows 首次装机（需要管理员，只需一次）

Docker Desktop 依赖 **WSL2**，而启用 WSL2 需要管理员权限 + 一次重启 —— 这一步无法在普通
终端里完成。仓库提供了 `scripts/setup-windows.ps1`，它会自动：

1. 启用 `Microsoft-Windows-Subsystem-Linux` 与 `VirtualMachinePlatform`
2. 设置 WSL 默认版本为 2
3. 静默安装 Docker Desktop（WSL2 后端）

**用法**

先下载 Docker Desktop 安装包（约 650MB，建议用 aria2 多线程加速）：

```bash
aria2c -c -x 16 -s 16 -d ~/Downloads -o DockerDesktopInstaller.exe \
  "https://desktop.docker.com/win/main/amd64/Docker%20Desktop%20Installer.exe"
```

然后**右键 PowerShell → 以管理员身份运行**：

```powershell
cd E:\Develop
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup-windows.ps1
```

脚本结束后**重启电脑**，再按 README「新协作者环境搭建」继续。

> 脚本不会帮你做两件事，因为 Docker Desktop 的 Engine 配置存在它自己的
> `settings-store.json` 里，外部写入会被覆盖，必须走 GUI：
> 1. 首次启动 Docker Desktop 并接受条款
> 2. 在 Settings → Docker Engine 里粘贴 §2.3 ③ 的 `registry-mirrors` JSON

**macOS / Linux 用户**：无需此脚本。macOS 直接 `brew install --cask docker`；
Linux 直接装 Docker Engine + Compose 插件即可，无 WSL 环节。

即可让 shadcn 组件直接呈现 Yuxi 观感。原型图 `doc/prototype/wenqu-prototype.html` 已按此规范实现；其 **「设计规范」页**把色板、按钮、标签、表单、分段控件、空态/骨架/提示/分页全部固化下来，可直接对照实现。

### 4.2 布局范式（Codex 式，Yuxi 与 SQLBot 一致）

两个参考项目（Yuxi、SQLBot）虽然组件库不同，但**信息架构完全一致**，均为 Codex / ChatGPT 式：

| 特征 | 说明 | WenQu 落地 |
|---|---|---|
| **无全局顶栏** | 侧边栏占满全高，内容区直接铺满；页面标题/操作放在各页面自己的头部条 | 已去掉顶栏，`page-head` / `page-bar` 承担标题与操作 |
| **侧栏以会话为主** | 品牌 → 「新建对话」→ **会话历史（占大部分）** → 底部资源入口与用户 | 导航项收敛为 5 个：新建对话、知识库、数据源、仪表盘、设置；会话列表占 `flex:1` |
| **RAG 与 SQLBot 不分入口** | 两者是**同一对话界面的两种模式**，而非两个独立模块 | 输入框**左下角**放模式切换胶囊（`.chip-select`），参照 Codex 的模型选择按钮；下拉仅两项 |
| **管理统一进「设置」** | 用户/模型/系统参数/操作日志集中在设置页签内管理 | `settings` 页内 4 个 tab（`.stab` + `.seg`） |
| **聊天为中心** | 登录后默认落在对话欢迎页（空态 + 推荐问题 + 底部输入框） | 默认路由 `/chat`，空态见原型 `chat-welcome` |
| **消息流 = 卡片流** | AI 回答由「步骤卡 → 代码块 → 结果表/图 → 引用 → 操作条」组成，而非纯文本气泡 | 见原型 `chat` / `sqlbot-query` |
| **SQL 域独立强调色** | SQLBot 用薄荷绿 `#1cba90` 区分于 RAG 的青蓝 | WenQu 沿用：shell/RAG 用 `--primary #24839b`，SQL 域（SQL 头像、执行按钮、数据源胶囊）用 `--mint #1cba90` |

## 5. 编码规范

### 5.1 Java

- 分层：`Controller → Service → Repository`；**Controller 不写业务**，Service 不碰 `HttpServletRequest`。
- DTO 与实体分离：`dto/request/*`、`dto/response/*`，实体仅内部使用。
- 校验：`@Valid` + JSR-380 注解；业务规则在 Service 抛 `BizException`。
- 异常：统一 `GlobalExceptionHandler`；禁止吞异常（至少 `log.warn` + 重抛或转换）。
- 事务：`@Transactional` 只加在 Service 的写方法；**注意**：SSE 生成过程不要长时间持有事务。
- 日志：`@Slf4j`；关键路径带 `traceId`；禁止打印 `apiKey`/`password`/完整 SQL 结果集。
- 命名：类 `UpperCamel`，方法/变量 `lowerCamel`，常量 `UPPER_SNAKE`，包全小写。
- 注释：仅在"为什么"不显然时写；禁止逐行解释"是什么"。
- 时间：统一 `OffsetDateTime`；DB 用 `timestamptz`。
- 金额：`BigDecimal`，禁止 `double` 做金额计算。

### 5.2 TypeScript / React

- 函数组件 + Hooks；禁止类组件。
- 服务端状态用 TanStack Query，客户端状态用 Zustand；**不要**把服务端数据塞进 Zustand。
- 类型：API 类型集中在 `types/`，与 `04-API接口规范.md` 字段一一对应（camelCase）。
- 请求统一走 `lib/http.ts` 的 axios 实例（注入 token、统一错误处理）。
- 组件命名 `PascalCase`，文件同名；hooks 以 `use` 开头。
- 禁止在 JSX 里写复杂逻辑，抽到 hooks。
- Tailwind：优先原子类；重复样式抽到 `components/ui`。

### 5.3 Git

- 分支：`main`（稳定）、`develop`（集成）、`feat/*`、`fix/*`。
- 提交信息：`feat(kb): 支持批量上传文档` / `fix(sqlbot): 修正 LIMIT 追加逻辑`（Conventional Commits）。
- 提交前：后端 `./mvnw -q verify`；前端 `pnpm lint && pnpm build`。
