## 技术选型变更（2026-10-13，已同步全部文档）
需求：MinIO 不可用 + 协作者在国内从零搭环境太难，要求重新选型并更新文档。

最终决策（用户拍板）：
1. 文件存储：MinIO → **本地文件系统**。抽象 `StorageService` 接口，`s3` 实现预留。
   下载从「MinIO 预签名 URL」改为「后端鉴权接口流式返回」（安全性反而更高）。
   根目录 `${WENQU_DATA_DIR:./.wenqu-data}/storage`，DB 只存相对路径。
2. 中文分词：zhparser（PG 扩展，需编译且 Windows 不可用）→ **应用层 Lucene smartcn**
   + PG 内置 `simple` 配置。`tsv` 从 GENERATED 列改为应用层显式写入的普通列。
   写入/查询必须用同一个分词器，否则召回失效。
3. **保留 RabbitMQ**（用户否决了我的「线程池 + DB 状态机」简化建议）
4. **保留 Redis**（用户否决了我的「Caffeine + PG 字段」简化建议）
5. PostgreSQL 获取方式：只留 Docker 单容器（不做本机安装脚本）
→ 基础设施从 4 容器（postgres+minio+redis+rabbitmq）收敛为 3 个，且无需自定义镜像编译任何扩展。

顺带闭环：`06-待确认事项` 的头号风险「LangChain4j 与 Spring Boot 4 兼容性」——
官方已明确支持 Boot 4（`-spring-boot4-starter` 后缀，要求 Java 17）。
但本项目仍不用其 Starter（LlmGateway 需按 llm_model 表运行时动态构建实例）。

  根目录 `.npmrc`（npmmirror）、根目录 `.gitignore`（含 .wenqu-data/）
